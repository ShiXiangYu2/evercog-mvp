## 三、主要问题清单

### 🔴 严重问题（P0）

#### P0-1: SystemUser 外键约束风险

- **文件位置**：`src/lib/agent/knowledge-accumulation/auto-filler.ts:52`
- **问题描述**：`creatorId: 'system'` 使用硬编码字符串，但 User 表中可能不存在 id 为 'system' 的用户
- **原因分析**：代码假设存在系统用户，但没有在 seed 数据中创建
- **影响范围**：知识卡自动填充功能可能失败
- **修复建议**：
  1. 在 seed.ts 中创建系统用户
  2. 或将 creatorId 改为可选字段
  3. 或使用真实的管理员用户 ID

```typescript
// 当前代码
creatorId: 'system',

// 建议修复
creatorId: await this.getSystemUserId(),
```

#### P0-2: 数据库 Schema 与代码不一致

- **文件位置**：`prisma/schema.prisma` + `src/lib/agent/task-executor.ts`
- **问题描述**：`AgentTask.result` 字段存储的是 input（创建时）和 output（完成时），语义混乱
- **原因分析**：创建任务时 `result: JSON.stringify(input)`，执行完成后又 `result: JSON.stringify(output)`
- **影响范围**：任务结果追溯困难
- **修复建议**：添加单独的 `input` 字段，或统一 `result` 的语义

#### P0-3: 缺少并发控制的全局锁

- **文件位置**：`src/lib/scheduler/scheduler.ts`
- **问题描述**：虽然有事务级别的并发控制，但缺少进程级别的锁
- **原因分析**：多实例部署时可能重复执行 Loop
- **影响范围**：Loop 重复执行
- **修复建议**：使用数据库 advisory lock 或 Redis 分布式锁

### 🟡 中等问题（P1）

#### P1-1: LLM 调用缺少超时控制

- **文件位置**：`src/lib/llm/index.ts:180`
- **问题描述**：`callLLMWithFallback` 没有设置全局超时
- **原因分析**：依赖 Provider 内部超时
- **影响范围**：LLM 调用可能长时间阻塞
- **修复建议**：添加 `AbortController` 超时控制

```typescript
// 建议添加
const controller = new AbortController()
const timeout = setTimeout(() => controller.abort(), LLM_TIMEOUT)
try {
  const result = await operation(provider)
  return result
} finally {
  clearTimeout(timeout)
}
```

#### P1-2: 缺少数据库连接池管理

- **文件位置**：`src/lib/prisma.ts`
- **问题描述**：没有配置 Prisma 连接池参数
- **原因分析**：使用默认配置
- **影响范围**：高并发时可能耗尽连接
- **修复建议**：添加连接池配置

```typescript
// 建议添加到 schema.prisma
datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")
  // 添加连接池配置（PostgreSQL）
  // directUrl = env("DATABASE_DIRECT_URL")
}
```

#### P1-3: 缺少 API 响应缓存

- **文件位置**：多个 API 路由
- **问题描述**：频繁查询的数据没有缓存
- **原因分析**：每次请求都查询数据库
- **影响范围**：性能瓶颈
- **修复建议**：添加内存缓存或 Redis 缓存

#### P1-4: 缺少请求体大小限制

- **文件位置**：`src/middleware.ts`
- **问题描述**：没有限制请求体大小
- **原因分析**：Next.js 默认不限制
- **影响范围**：可能遭受 DoS 攻击
- **修复建议**：添加 body size 限制

#### P1-5: 缺少 CORS 配置验证

- **文件位置**：`src/middleware.ts:10`
- **问题描述**：CORS_ORIGIN 默认为 localhost
- **原因分析**：开发环境配置可能被用于生产
- **影响范围**：安全风险
- **修复建议**：生产环境强制配置 CORS_ORIGIN

## 四、详细维度评估

### 4.1 项目架构

#### 优点

1. ✅ **分层清晰**：表现层、API 层、服务层、数据层职责明确
2. ✅ **模块化设计**：按功能模块组织，易于理解和维护
3. ✅ **插件化架构**：Agent Executor 可插拔，易于扩展
4. ✅ **事件驱动**：EventBus 实现模块间解耦
5. ✅ **依赖注入**：单例模式 + 工厂模式，易于测试

#### 问题

1. ⚠️ **缺少依赖注入容器**：单例模式可能导致测试困难
2. ⚠️ **缺少缓存层**：频繁查询数据库可能影响性能
3. ⚠️ **缺少消息队列**：异步任务可能阻塞主线程
