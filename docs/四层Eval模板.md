# 恒识 Evercog MVP 四层 Eval 模板

> 基于 AutoDev Framework 的四层 Eval 标准，用于验证项目是否达到交付要求

---

## Eval Summary

**目标功能**：恒识 Evercog MVP 全部核心功能

**成功定义**：
- 真实用户可完成核心业务流程
- AI 功能可真实调用
- 安全配置符合生产要求
- 服务稳定可用

**验证方式**：
- 自动化测试
- 手动功能测试
- 安全扫描
- 性能测试

---

## 一、功能正确层

验证系统是否做对了。

### 核心用户路径

- [ ] **登录认证**：用户可正常登录，JWT 有效
- [ ] **政策链接池**：可提交、查看、审核政策链接
- [ ] **政策简报**：AI 可生成简报，用户可审核和推送
- [ ] **知识卡管理**：可创建、审核、检索知识卡
- [ ] **经验问答**：可输入问题，获得 AI 回复
- [ ] **SOP 训练**：可布置任务、提交、审核
- [ ] **审计日志**：关键操作有记录
- [ ] **权限控制**：不同角色权限正确

### 业务规则

- [ ] 状态流转符合设计（草稿→待审核→已审核→已发布）
- [ ] 权限检查覆盖关键操作
- [ ] 数据验证使用 Zod schema
- [ ] 错误信息明确可理解

### 验证方式

```bash
# 运行单元测试
npm test

# 手动测试核心流程
# 1. 登录系统
# 2. 提交政策链接
# 3. 生成政策简报
# 4. 创建知识卡
# 5. 进行经验问答
# 6. 查看审计日志
```

### 自定义标准

- [ ] AI 生成的简报内容准确、相关
- [ ] 知识卡搜索结果按相关度排序
- [ ] 经验问答回复包含引用来源

---

## 二、性能安全层

验证系统是否稳定、安全、成本可控。

### 数据安全

- [ ] JWT 密钥为强随机字符串（≥32位）
- [ ] 密码使用 bcrypt 哈希存储
- [ ] 敏感数据不在日志中输出
- [ ] HTTPS 启用（生产环境）
- [ ] CORS 配置正确

### 性能指标

- [ ] 首屏加载时间 < 3 秒
- [ ] API 响应时间 < 1 秒
- [ ] 数据库查询时间 < 500ms
- [ ] 并发用户数 > 50

### 外部服务

- [ ] LLM API 调用有超时设置
- [ ] LLM API 失败有降级机制
- [ ] 外部 API 调用有重试逻辑
- [ ] API 调用成本可控（有预算告警）

### 限流控制

- [ ] 匿名用户限流：60 次/分钟
- [ ] 认证用户限流：120 次/分钟
- [ ] 登录接口限流：10 次/分钟
- [ ] 速率限制响应包含 Retry-After 头

### 验证方式

```bash
# 安全扫描
npm audit

# 性能测试
# 使用 Apache Bench 或 Artillery
ab -n 1000 -c 10 http://localhost:3000/api/health

# 检查 HTTPS
curl -I https://your-domain.com
```

### 自定义标准

- [ ] 无高危安全漏洞
- [ ] 敏感配置不在代码中硬编码
- [ ] 数据库连接池配置合理

---

## 三、边界异常层

验证系统在坏情况和边界条件下是否可靠。

### 输入验证

- [ ] 空输入有明确处理（400 错误）
- [ ] 格式错误有明确反馈
- [ ] 超长输入有截断或拒绝
- [ ] 特殊字符处理正确

### 重复提交

- [ ] 重复登录不会创建多个会话
- [ ] 重复提交表单不会产生重复数据
- [ ] 幂等性设计正确

### 网络失败

- [ ] 网络断开有友好提示
- [ ] 请求超时有重试机制
- [ ] 服务不可用有降级方案

### 下游服务

- [ ] LLM 服务不可用时有 Mock 降级
- [ ] 数据库连接失败有错误提示
- [ ] 外部 API 失败有日志记录

### 数据异常

- [ ] 数据缺失有默认值处理
- [ ] 数据格式错误有验证提示
- [ ] 权限不足有明确拒绝信息

### 验证方式

```bash
# 测试空输入
curl -X POST http://localhost:3000/api/auth/login -H "Content-Type: application/json" -d '{}'

# 测试重复提交
# 使用脚本连续发送相同请求

# 模拟网络失败
# 断开网络后测试应用行为
```

### 自定义标准

- [ ] 错误页面用户友好
- [ ] 错误日志包含足够调试信息
- [ ] 异常不会导致应用崩溃

## 四、业务价值层

验证系统是否产生可观察的效率、质量、风险或业务收益。

### 效率提升

- [ ] 政策情报采集时间减少（目标：从 2 小时减少到 10 分钟）
- [ ] 知识检索时间减少（目标：从 30 分钟减少到 1 分钟）
- [ ] 新人培训周期缩短（目标：从 2 周减少到 3 天）

### 质量改善

- [ ] 政策简报生成准确率 > 80%
- [ ] 知识卡搜索相关度 > 70%
- [ ] 经验问答回复可用率 > 60%

### 风险降低

- [ ] 政策遗漏率降低（目标：从 20% 降低到 5%）
- [ ] 知识断层可及时发现
- [ ] 操作可追溯（审计日志）

### 用户体验

- [ ] 用户满意度 > 70%
- [ ] 核心功能使用率 > 50%
- [ ] 用户留存率 > 40%
