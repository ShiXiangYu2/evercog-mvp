## 一、Bug 模式

### BUG-01: LLM Provider 单例竞态 ⚠️
**严重度**: 中
**位置**: `src/lib/llm/index.ts:32-69`

```typescript
let _provider: LLMProvider | null = null

export function getLLMProvider(): LLMProvider {
  if (_provider) return _provider  // ← 竞态窗口
  // ... 初始化逻辑
}
```

**问题**: 在并发请求场景下，多个请求可能同时进入 `getLLMProvider()`，导致多次初始化。虽然结果相同（幂等），但浪费资源。

**修复建议**: 使用 `Promise` 或 `Mutex` 保证单例初始化原子性。

### BUG-02: Rate Limiter 内存泄漏 ⚠️
**严重度**: 中
**位置**: `src/lib/rate-limit.ts:39-49`

```typescript
const store = new Map<string, WindowRecord>()

setInterval(() => {
  const now = Date.now()
  for (const [key, record] of store.entries()) {
    if (now > record.resetAt) {
      store.delete(key)
    }
  }
}, 60000)
```

**问题**:
1. `setInterval` 在测试环境中不会被清理，可能导致测试间状态泄漏
2. 高并发场景下，Map 可能无限增长（清理周期 60s，窗口也是 60s）
3. 在 serverless 环境中，`setInterval` 不可靠

**修复建议**: 改用 LRU 缓存或 Redis，测试中使用 `vi.useFakeTimers()`。

## 二、安全问题

### SEC-01: JWT Secret 默认值仍可被使用 🔴
**严重度**: 高
**位置**: `src/lib/jwt.ts:33-38`

```typescript
function getSecret(): Uint8Array {
  const secret = process.env.JWT_SECRET
  if (!secret) {
    throw new Error('JWT_SECRET environment variable is required')
  }
  return new TextEncoder().encode(secret)
}
```

**问题**: 虽然代码要求必须设置，但 `.env` 中的默认值 `change-this-to-a-strong-random-string-in-production` 可以通过校验。生产环境不会自动检测这个弱密钥。

**修复建议**: 启动时检查 `JWT_SECRET` 是否为默认值，如果是则拒绝启动。

---

### SEC-02: 旧版 X-User-Id Header 在非生产环境仍可用 ⚠️
**严重度**: 中
**位置**: `src/lib/auth.ts:75-80`

```typescript
if (process.env.NODE_ENV !== 'production') {
  const legacyUserId = request.headers.get('x-user-id')
  if (legacyUserId) {
    return { type: 'legacy', userId: legacyUserId }
  }
}
```

**问题**: 开发/测试环境中，任何人都可以通过 `X-User-Id` header 冒充任意用户。如果 staging 环境的 `NODE_ENV` 不是 `production`，此漏洞可用。

**修复建议**: 添加显式的 `ALLOW_LEGACY_AUTH` 环境变量控制。

---

### SEC-03: SQL LIKE 查询未转义通配符 ⚠️
**严重度**: 低
**位置**: 多个 Service 的搜索功能

```typescript
// KnowledgeCardService
if (search) {
  where.OR = [
    { title: { contains: search } },
    { content: { contains: search } },
  ]
}
```

**问题**: Prisma 的 `contains` 在 SQLite 中使用 `LIKE`，用户输入的 `%` 和 `_` 会被当作通配符，可能导致意外匹配。

**修复建议**: 在搜索前转义 `%` 和 `_`。

### QL-03: Prisma 查询未使用事务 ⚠️
**严重度**: 中
**位置**: 多个 Service

```typescript
// PolicyBriefService.afterTransition
await prisma.policyBrief.update({ ... })
await prisma.policyLink.update({ ... })  // ← 如果这里失败，数据不一致
```

**问题**: 多个数据库操作未使用事务，部分失败会导致数据不一致。

**修复建议**: 使用 `prisma.$transaction([ ... ])` 包裹关联操作。

### PERF-01: 知识卡搜索全量加载后内存过滤 ⚠️
**严重度**: 中
**位置**: `src/lib/services/knowledge-card.ts:156-174`

```typescript
async list(filters, user) {
  const result = await super.list(filters, user)  // ← 已分页

  // 再次过滤
  const filteredItems = result.items.filter((card) =>
    canViewKnowledgeCard(user, { ... })
  )

  return {
    ...result,
    items: filteredItems,
    total: filteredItems.length,  // ← total 不准确
  }

```

**问题**:
1. 先分页再过滤，可能导致返回的 items 数量 < pageSize
2. `total` 是过滤后的数量，不是数据库中的总数
3. 分页信息不准确

**严重度**: 低
**位置**: `src/lib/audit.ts:28-43`

```typescript
export async function createAuditLog(params: AuditLogParams): Promise<void> {
```
