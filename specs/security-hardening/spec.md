# PRD: 安全加固与生产化

## 1. 背景与目标

基于项目评审报告（得分 82.5/100，评级 B+），需要完成以下高优先级安全加固任务，使系统达到生产环境部署标准。

**目标**：将系统安全评分从 75 分提升至 90 分以上。

## 2. 用户故事

### 2.1 Rate Limiting
- **作为**系统管理员，**我希望** API 请求被合理限制，**以便**防止恶意攻击和资源滥用
- **作为**正常用户，**我希望**在合理使用时不受限制，**以便**正常使用系统功能

### 2.2 CORS 配置
- **作为**前端开发者，**我希望** CORS 正确配置，**以便**前端应用能正常调用 API
- **作为**系统管理员，**我希望** CORS 可配置，**以便**控制允许访问的来源

### 2.3 LLM 超时处理
- **作为**用户，**我希望** LLM 调用有超时限制，**以便**不会长时间等待
- **作为**系统管理员，**我希望**超时后有降级方案，**以便**系统仍可使用

### 2.4 密码登录
- **作为**用户，**我希望**使用密码登录，**以便**更安全地访问系统
- **作为**系统管理员，**我希望**密码安全存储，**以便**保护用户账户

## 3. 功能需求

### 3.1 Rate Limiting

| 需求 | 优先级 | 描述 |
|------|--------|------|
| FR-1.1 | P0 | 按 IP 限制匿名用户请求 |
| FR-1.2 | P0 | 按用户 ID 限制认证用户请求 |
| FR-1.3 | P0 | 返回 429 状态码和 Retry-After 头 |
| FR-1.4 | P1 | 支持白名单（管理员 IP） |
| FR-1.5 | P1 | 支持自定义限制规则 |

**限制阈值**：
- 匿名用户：60 次/分钟
- 认证用户：120 次/分钟
- 登录接口：10 次/分钟

### 3.2 CORS 配置

| 需求 | 优先级 | 描述 |
|------|--------|------|
| FR-2.1 | P0 | 支持环境变量配置允许的源 |
| FR-2.2 | P0 | 支持 Cookie 凭证 |
| FR-2.3 | P0 | 允许常用 HTTP 方法 |
| FR-2.4 | P1 | 支持预检请求缓存 |

**默认配置**：
```env
CORS_ORIGIN="http://localhost:3000"
CORS_METHODS="GET,POST,PUT,DELETE,OPTIONS"
CORS_CREDENTIALS="true"
```

### 3.3 LLM 超时处理

| 需求 | 优先级 | 描述 |
|------|--------|------|
| FR-3.1 | P0 | 支持配置超时时间 |
| FR-3.2 | P0 | 超时后返回明确错误 |
| FR-3.3 | P1 | 支持降级到 Mock 模式 |
| FR-3.4 | P1 | 记录超时事件到日志 |

**配置参数**：
```env
LLM_TIMEOUT="30000"  # 30 秒
LLM_FALLBACK_TO_MOCK="true"
```

### 3.4 密码登录

| 需求 | 优先级 | 描述 |
|------|--------|------|
| FR-4.1 | P0 | 密码 bcrypt 哈希存储 |
| FR-4.2 | P0 | 支持 userId + password 登录 |
| FR-4.3 | P0 | 登录失败锁定策略 |
| FR-4.4 | P1 | 密码强度验证 |
| FR-4.5 | P2 | 密码重置功能（暂不实现） |

**密码策略**：
- 最小长度：8 位
- 必须包含：字母和数字
- 最大尝试次数：5 次
- 锁定时间：15 分钟

## 4. 非功能需求

### 4.1 性能
- NFR-1.1: Rate Limiting 检查延迟 < 10ms
- NFR-1.2: CORS 预检请求响应 < 50ms

### 4.2 安全
- NFR-2.1: 密码使用 bcrypt 哈希（12 轮 salt）
- NFR-2.2: JWT Secret 至少 32 位
- NFR-2.3: 敏感信息不记录到日志

### 4.3 可用性
- NFR-3.1: Rate Limiting 误报率 < 1%
- NFR-3.2: LLM 超时后系统仍可用

## 5. 技术方案

### 5.1 Rate Limiting
- 使用内存存储（Map）
- 滑动窗口算法
- 中间件形式集成

### 5.2 CORS
- 使用 Next.js 内置 CORS 支持
- 在 middleware.ts 中配置

### 5.3 LLM 超时
- 使用 AbortController 实现超时
- 在 LLM Provider 中集成

### 5.4 密码登录
- 使用 bcryptjs 库
- 扩展 User 模型添加 passwordHash 字段
- 更新登录 API

## 6. 验收标准

### 6.1 Rate Limiting
- [ ] 匿名用户超过 60 次/分钟返回 429
- [ ] 认证用户超过 120 次/分钟返回 429
- [ ] 响应头包含 Retry-After

### 6.2 CORS
- [ ] 前端应用能正常调用 API
- [ ] 预检请求正确响应
- [ ] 支持 Cookie 凭证

### 6.3 LLM 超时
- [ ] 超过 30 秒返回超时错误
- [ ] 支持降级到 Mock 模式
- [ ] 超时事件记录到日志

### 6.4 密码登录
- [ ] 密码正确能登录成功
- [ ] 密码错误返回 401
- [ ] 连续 5 次失败锁定 15 分钟
- [ ] 密码使用 bcrypt 哈希存储

## 7. 风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Rate Limiting 误报 | 正常用户被限制 | 提供白名单机制 |
| CORS 配置错误 | 前端无法调用 API | 默认配置允许 localhost |
| LLM 超时影响体验 | 用户等待时间长 | 提供降级方案 |
| 密码安全风险 | 账户被破解 | 强制密码策略 |
